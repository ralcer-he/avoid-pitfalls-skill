## 一、手机端适配

### 1.1 顶部栏必须给状态栏留高度（安全区 / edge-to-edge）

**问题**：顶部栏与手机状态栏重合，按钮点不到、标题被遮。

**根因**：Android 15+ 对 targetSdk 35+ 的应用**强制 edge-to-edge**——状态栏悬浮在 WebView 上方，且 WebView **默认不提供安全区**（`env(safe-area-inset-top)` 拿不到值，那是 iOS 的）。

**解法（三件套 + 双保险）**：
1. `index.html` 的 `<meta viewport>` 加 `viewport-fit=cover`；
2. 运行时用 Capacitor `StatusBar.getInfo()` 实测状态栏高度，注入 CSS 变量（WebView 不注入安全区，必须手动实测）：
   ```js
   const info = await StatusBar.getInfo()
   if (info.height > 0) document.documentElement.style.setProperty('--sat', `${info.height}px`)
   ```
3. CSS 用 `max()` 做**双保险兜底**（`--sat` 是实测值，20px 是最小兜底）：
   ```css
   .safe-area-top { padding-top: max(env(safe-area-inset-top, 0px), var(--sat, 0px), 20px); }
   ```
4. 顶部栏固定高度：`minHeight: 44px + paddingTop: var(--safe-area-top, 0px)`；弹窗/日期选择器从顶部定位时 `top: calc(44px + var(--safe-area-top, 0px))`；
5. 底部固定栏叠加 `env(safe-area-inset-bottom)`，页面内容留 `padding-bottom` 防被底部导航遮挡；
6. `StatusBar.setOverlaysWebView({ overlay: true })` 沉浸式布局，配合 CSS 变量手动避让。

**教训**：edge-to-edge 是**默认行为不是可选项**——所有"贴边"的 UI 都要主动避让，别指望系统帮你；状态栏高度**异步获取 + 失败兜底**（Web 端没有状态栏，先 `Capacitor.isNativePlatform()` 排除）。

### 1.2 输入框必须自适应软键盘（踩得最深的坑）

**问题 A：输入框被键盘挡住 / 不随键盘上移**
- 软键盘弹出后 `window.innerHeight` 取不到键盘区，悬浮按钮/菜单定位错乱 → 用 `visualViewport`；
- edge-to-edge 下 `adjustResize` 失效 → 输入区容器用 **`position: fixed; bottom: 0`**，Chromium 对 fixed 底部元素**自动随键盘避让**（无需 JS）；消息列表底部补 `padding-bottom: calc(输入区高度 + 键盘高变量)`。

**键盘高度的获取（关键）**：
- Capacitor Keyboard 事件 + `visualViewport` 双通道；高度变化用阈值（diff>100 弹出 / diff<50 收起）防抖动；iOS Safari 可能只触发 scroll，`resize` 和 `scroll` 都监听；
- **键盘高度只写 CSS 变量（如 `--kb-h`），不要用 React setState 存**——setState 触发重渲染会干扰输入法（语音听写实测踩坑）：
  ```js
  document.documentElement.style.setProperty('--kb-h', `${height}px`) // 只改 CSS 变量，不触发任何 React 渲染
  ```
- 键盘显示时给 `body` 加 `keyboard-open` class，CSS 统一隐藏悬浮元素：
  ```css
  body.keyboard-open .fab-container { display: none !important; }
  ```
- `capacitor.config.json`：`Keyboard.resize: "native"`、`overlaysWebView: false`、`resizeOnFullScreen: true`；
- 页面高度用 `h-dvh`（动态视口），**不要用 `h-screen`**。

**问题 B：语音输入错乱（"你好" → 重复插入"你好你好你好？"）**

**血泪教训**：**不是输入框代码的问题**，是两个"多余的配置"干扰了输入法：
1. viewport meta 里的 `interactive-widget=resizes-content`；
2. Capacitor 配置里的 `android.captureInput: true`。

这两个开关会让浏览器在键盘弹出瞬间反复"调整网页"，语音输入法误以为输入框状态变了而重复插入识别结果。**移除后立即正常**。且输入框组件最终**完全照搬能正常工作的参照 app 的朴素受控 `<input>`**——不做任何"增强"（不加 onPaste、不加焦点滚动），任何"防干扰"改造都可能再踩输入法雷。中文输入法防误发：`if (e.key === 'Enter' && !e.nativeEvent.isComposing)`。

**排查方法论（最重要的一条）**：遇到输入法/键盘类怪问题，**先和"能正常工作的参照 app"逐项对比原生配置**（viewport meta、capacitor.config.json、Keyboard 插件配置、windowSoftInputMode、targetSdk），**差异项优先怀疑**——不要先在 Web 层反复改代码。曾有人在 Web 层折腾 5+ 轮无效，对比配置 10 分钟定位。

### 1.3 页面适配：避免拥挤、遮挡、点不到

| 问题 | 解法 |
| --- | --- |
| 键盘弹出遮住底部按钮（"下一步"点不了） | 键盘避让修好后自动解决；按钮放页面底部时预留键盘空间 |
| 弹窗/Dialog 定位错乱 | **必须 `createPortal(..., document.body)`**——父容器有 backdrop-filter/transform/overflow 会破坏 fixed 定位 |
| 弹层内容超屏 | 容器 `max-h-[90vh] overflow-y-auto` |
| 弹层点外部关不掉 | onClose 绑外层、内容卡片 `e.stopPropagation()` |
| Dropdown 关闭瞬间误点下层（ghost click 穿透） | 三重防线：遮罩延迟保留 450ms + 文档捕获阶段 350ms 全局拦截 + 菜单项 `stopPropagation` |
| 刘海屏/底部横条遮挡 | fixed 元素加 `pt/pb max(1rem, env(safe-area-inset-top/bottom))` |
| 工具栏挤占空间/换行 | 按钮紧凑化（32→28px）、减间距、加 `overflow-x-auto` 横向滚动安全网 |
| 卡片/弹窗样式不统一 | 统一「白底 + 1px 细边框 + 中等圆角（12px）」，三层阴影规范 |
| 超长文本撑爆布局 | 加 `title` 完整展示 + 省略号 |
| 彩色标签看不清 | 「白底 + 彩边」而非「同色淡底 + 同色文字」 |

**移动端字号规范**：标题 18 / 区块 16 / 正文 14 / 辅助 13 / 标签 12px，**禁止 12px 以下**（iOS 会强制缩放）；输入控件统一 16px。

**触摸优化全家桶**：`-webkit-tap-highlight-color: transparent`、`touch-action: manipulation`（消 300ms 延迟）、`overscroll-behavior-y: none`（防橡皮筋）、全局禁选 `user-select: none` 但**输入框/聊天消息单独放行**。

### 1.4 触摸 / 鼠标事件双通道

**问题**：`touchend` 后浏览器模拟触发 `mouseup`/`click` → 拖拽逻辑执行两次；`touchstart` 后约 300ms 触发 `mousedown`。

**解法**：
- `touchEndHandled` ref 标志去重 + 500ms 超时兜底清除；`touchstart` 后 `mousedown` 直接 return；
- 两个通道需要**两个独立标志**（mousedown 会清另一个 ref）；
- `touchmove` 要 `preventDefault` 时注册 `{ passive: false }`；
- 拖拽 vs 点击：移动 >3px 判拖拽；短触摸（<200ms）即使微动也视为点击。

### 1.5 Android 返回键

- 统一监听 `@capacitor/app` 的 `backButton`，五级优先级：侧边栏 → 弹出层(`data-overlay`) → 弹窗(`data-modal-open`) → 路由回退 → 双击退出；
- 组件通过监听自定义事件 `CustomEvent('backbutton')` 自治响应（解耦）；
- 双击退出：2 秒内再按 `CapacitorApp.exitApp()`，第一次按 Toast 提示；
- 处理器闭包访问的最新 state 必须加入 `useEffect` 依赖数组。

### 1.6 移动端性能

- **图片存 base64 前必须压缩**：手机照片 5-12MB → 最长边 2048px/JPEG 85% → 200-500KB（或 1280px/0.8/单张 1.5MB 的配置）；
- **PNG→JPEG 必须先铺白底**，透明区转 JPEG 会变黑；
- 画板 Canvas 移动端限制最大宽度、用完释放临时对象；
- APK 体积三件套：`minifyEnabled` + `shrinkResources` + ABI 过滤（78MB→2MB）；体积异常先查代码分割配置（曾因 465 个 JS 重复打包 React 导致 62MB）。

## 二、权限管理

> 核心教训：**Web API 权限在 WebView 中不是自动弹窗的**，需要「原生 manifest 声明 + 运行时主动触发」两步走。

- **麦克风**：Android WebView 中 `webkitSpeechRecognition` 不会自动弹系统麦克风授权 → 先 `getUserMedia({ audio: true })` 主动触发，拿到流立即 `stop()`，再开始识别；`AndroidManifest.xml` 声明 `RECORD_AUDIO`；错误分类处理（`not-allowed` 引导授权、`no-speech` 静默、其他通用提示）；
- **通知**：Web Notification API 在 Android WebView 中基本不可用、`setTimeout` 后台被挂起 → 用 `@capacitor/local-notifications` 原生通知（`repeats: true` 每日定时，先 cancel 旧再建新）；Android 13+ 需运行时权限 `POST_NOTIFICATIONS`（插件会自动合并进 manifest）；浏览器权限一旦被拒再调 `requestPermission()` 不弹窗，先判断 `permission !== 'denied'`；通知 ID 用 `Date.now() % 2147483647` 防超 int32；**通知类功能必须提供「测试通知」按钮**；
- **`INTERNET` 权限**：Capacitor 默认带，但**一旦漏配所有联网功能静默全挂**——排查过整个"联网搜索失效"，根因就是它；
- **文件导出**：原生环境 `a.download` 不可用 → 封装跨平台工具，原生用 `@capacitor/share`；
- **API key 输入框不要用 `type="password"`**：部分手机输入法在 password 框禁用粘贴，用户只能手输 40 位 key。用 `type="text"` + 失焦 trim；
- 相机/相册/存储：manifest 声明 + 运行时请求，用户拒绝要有兜底（不能崩溃）。

## 三、桌面端打包（EXE）

### 3.1 必须打包成安装程序（setup），不是裸 exe / 绿色版

**问题**：交付裸目录/裸 exe，用户机器没有 Node、构建环境或对应运行时，双击直接失败——用户只会觉得"你的软件是坏的"。

**解法（Tauri 为例）**：
```powershell
npm run tauri:build
# 产物：src-tauri/target/release/bundle/nsis/xxx_x64-setup.exe（NSIS 安装向导）
```
- **WebView2 必须 `offlineInstaller`**（内置完整运行时约 130MB）：任何 Windows 都能跑；`embedBootstrapper` 只带在线安装器，用户机器可能没有 WebView2 → 装了打不开（白屏）。包大 130MB 换"一定能跑"，值；
- 分发的是 `bundle/nsis/` 里的 setup.exe，**不是** `target/release/*.exe`（裸 exe 没捆绑运行时）；
- `installMode: "both"` 支持当前用户/所有用户；
- 桌面壳（Electron 等）约定：electron-builder + NSIS，`nsis.oneClick: false`、可自定义安装目录、开始菜单快捷方式、卸载入口；**不允许免安装绿色版/便携版**；
- 首次 `tauri build` 编译 Rust 5-15 分钟，之后 1-2 分钟——**别误以为卡死**；报 "Microsoft Visual Studio" 错误 → 装 **Visual Studio Build Tools**。

### 3.2 桌面端其他要点

- 窗口尺寸设计为手机竖屏比例（如 430×900），保持移动优先 UI 一致性；
- Tauri 环境检测同时判断 `window.__TAURI__`（v1）和 `window.__TAURI_INTERNALS__`（v2）；打开外链必须用 `@tauri-apps/plugin-shell` 的 `open()`；
- Tauri 必须显式配置 CSP；
- 图标：`npx tauri icon <源图.png>` 一键生成全平台图标；Windows 换图标后**必须清图标缓存**（taskkill explorer + 删 IconCache.db + 重启）才看得到效果。

## 四、移动端打包发布（APK）

### 4.1 打包顺序（最容易踩的坑）

**「修了 bug 但 APK 没变」的最常见原因**：Capacitor 不会自动重建前端，`cap sync` 只是把 `dist/` 复制进 Android 工程。

```powershell
npm run build                          # 1. 先构建前端
# 2. 清理旧资源再同步（避免带 hash 的 assets 文件累积）
if (Test-Path "android\app\src\main\assets\public") {
  Remove-Item -Recurse -Force "android\app\src\main\assets\public"
}
npx cap sync android                   # 3. 同步
cd android
.\gradlew.bat clean                    # 4. 每次 clean 防旧产物残留（只靠增量编译会踩"旧资源"bug）
.\gradlew.bat assembleRelease          # 5. 构建（不要用 npx cap build android）
```

> 可以把清理逻辑写进 npm 脚本（`"cap:sync": "if exist android\\app\\src\\main\\assets\\public rmdir /s /q ... && cap sync"`）。**不要只靠增量编译**。

### 4.2 签名与发布

- 发布包必须签名（`apksigner verify` 验证）；**keystore 文件 + 密码必须妥善保存**——丢了无法覆盖安装升级（只能卸载重装，数据全丢）；
- ⚠️ **keystore 密码不要明文写死在 build.gradle**，keystore 文件必须进 `.gitignore`——仓库外泄 = 攻击者可发"同签名"恶意覆盖包。密码应经环境变量 / CI secret 注入；
- **`versionCode` 必须递增**——覆盖安装升级依赖它，每轮交付前 +1；
- 产物重命名规范：`app_v{版本}.apk`；
- 应用名改三处：`strings.xml` 的 `app_name` + `title_activity_main` + Web 端 `<title>`；
- 图标：adaptive icon 要**前景图（透明底）+ 背景色**分开；Android 自适应图标会裁切前景层，内容缩放至画布 **56%** + 透明边距；
- **项目路径避免中文/空格**（曾导致 Gradle 构建失败，必要时 `android.overridePathCheck=true`）；
- `android/` 目录通常被 gitignore：clone 后 `npx cap add android` 初始化，靠 `cap sync` 生成，不手改其中文件。

### 4.3 每轮交付给用户的信息

APK 路径 + preview URL（`vite preview` 构建版）+ "覆盖安装"说明；生产行为**以构建版为准**，不要用 dev server（HMR/懒加载有干扰）。

## 五、多端兼容：WebView ≠ 浏览器

> 最大认知：**WebView（Tauri/Capacitor 壳）不是浏览器**，PWA 时代的方案在原生壳里反而是干扰。

| 能力 | Web/PWA | 原生壳 | 教训 |
|------|---------|--------|------|
| Service Worker | 正常缓存 | **必须主动注销**，否则缓存旧代码/白屏 | index.html 内联脚本在模块加载**前**检测原生环境并 unregister + 清 Cache；vite `injectRegister: null` 不自动注册 |
| 通知 | Notification API | Capacitor LocalNotifications | 见权限章节 |
| 剪贴板 | `navigator.clipboard` | 部分 WebView 不支持 | 降级链：Clipboard API → `execCommand('copy')` |
| 语音 | Web Speech API | Android WebView 不稳定 | 能力检测 + 降级；不稳定的移动端功能**宁可隐藏** |
| 文件下载 | `a.download` | 不可用 | `@capacitor/share` |
| 数据存储 | IndexedDB 按域名隔离 | `tauri://`/`capacitor://` 协议隔离 | Web 版与原生版数据不互通，迁移需手动导入导出 |
| 浏览器差异 | 语音：Chrome/Edge 好，Safari 部分，Firefox 不支持 | — | 设计阶段查 API 兼容矩阵 + 前缀兜底 + 提示换浏览器 |

## 六、前端工程与状态管理

### 6.1 React 通用坑

- **对 DOM 唯一绑定的库（编辑器/图表/canvas）绝不能同时渲染两个实例**（CSS hidden 也不行）→ 用条件渲染；
- **闭包陷阱**：拖拽/动画高频回调用 `ref` 读最新值，不用 state（`useCallback` 捕获旧值）；优先级：ref > useEffect 内联 > 函数式更新；
- 避免 `document.querySelector` 直接操作 DOM，用事件委托 + `e.target.closest()`；
- **多组件实例并发初始化**：响应式布局同一页面渲染多次 → 初始化加全局 Promise 锁 + 幂等函数 + ref 防重复（3 个实例并发创建 3 条数据的教训）；
- 轻量跨组件同步用 `CustomEvent`，别引状态库；
- 日期处理**永远用本地时区**，`toISOString()` 是 UTC 陷阱（凌晨记录被分到前一天）；
- HTML 实体（如 `&nbsp;`）：正则去标签不解码实体，用基于 DOM 的工具函数；
- `preventDefault` on mousedown 会阻止 click：拖拽按钮在 mouseup 判断移动距离触发；
- 批量 DOM 操作改增量更新（曾因批量插文本引发 React Error #185 无限重渲染）。

### 6.2 zustand / 状态管理

- **selector 必须稳定引用**：`(s) => ({ a: s.a, b: s.b })` 每次返回新对象 → 无限重渲染。标准姿势：先 select 稳定引用，再 `useMemo` 派生合并对象；
- **内联空数组/空对象字面量 `?? []` 也导致无限重渲染**——空数组/空对象提取为模块级常量；
- 组件渲染中重建对象/数组字面量会让 useCallback/useEffect 依赖每次变化 → 死循环请求：用 `useMemo` 固定，依赖用具体字段而非整个对象；
- **selector 保持纯函数**：不要在 selector 里调带副作用（set）的 action 做惰性初始化（StrictMode 双渲染会执行两次 set）；
- **persist 的 `merge` 是数据迁移的自然钩子**：旧结构判断 → 转换 → 返回合并态，无需手动脚本；
- **修改 store 数据结构必须提升 persist 的 `version`**，否则旧数据残留导致异常；
- **跨 store 循环依赖用动态 `import()`** 在运行时取模块；
- 跨 store 派生统计在异步回调和删除竞争下会失真"复活" → 判断数据是否仍存在再递增 + 一次性"从真实数据重算"迁移任务（带 localStorage 标记，幂等）。

### 6.3 TypeScript / Vite / Tailwind

- `noUnusedLocals` / `noUnusedParameters` 严格模式开着，声明没用的变量直接编译报错；
- **Vite 8 (rolldown) 的 `manualChunks` 只接受函数形式**，对象形式构建报错（版本升级会改打包 API 形态）；
- **所有 className 合并必须走 `cn()`**（clsx + tailwind-merge），否则条件 class 覆盖问题防不胜防；
- 跨目录 import 用路径别名 `@/xxx`，不要 `../../..`；
- Tailwind v4 双写：`@theme` 定义 token + `:root`/`[data-theme=dark]` 再写一份同名 CSS 变量（JS 里 `style={{...}}` 也能读 var）；
- dev server 的 watch 忽略编辑器/工具目录（`.reasonix`、`.git`、`dist`、`android` 等），否则编辑器写入触发 watcher 卡顿/误 reload；
- **"UI 标可选但逻辑判必填"是经典 bug**：表单 UI 标注和校验函数必须同源；**"UI 有开关但逻辑从未实现"**（设置页有开关、代码里无执行逻辑）——要么实现要么隐藏开关；
- 分段/排序/复用逻辑不要多处各写一套：抽共享函数。

### 6.4 输入法 / 键盘相关

- 输入框组件保持**朴素受控 input**（见 1.2 问题 B）；
- `Enter` 发送 / `Shift+Enter` 换行，用 `e.nativeEvent.isComposing` 防中文输入法选词时误发送；
- 键盘高度 CSS 变量方案中，**旧的 setState 版本 Hook 要及时删除或标注废弃**（死代码与文档冲突会误导后人）。

## 七、数据持久化与备份

### 7.1 localStorage 5MB 配额 → IndexedDB 迁移（移动端数据血泪）

**问题**：图片 base64 塞 localStorage 很快撞 5MB 配额——写入抛错、数据静默丢、新数据被旧数据覆盖。

**最终方案**：
1. **整体迁移到 IndexedDB**：zustand persist 的 StateStorage 支持返回 Promise，配额通常 50MB+；
2. **迁移必须在任何 persist store 模块加载之前执行**（动态 import store 前 await 迁移函数），否则 hydrate 读到空库；用标记（如 `__migrated_v1__`）幂等；**不删除 localStorage 旧数据**（回退友好）；
3. **所有 store 的 `rehydrate()` 全部 await 后再 `createRoot`**——IndexedDB 读取异步，防止首帧渲染空数据后被真实数据覆盖导致闪烁；
4. 即使迁到 IndexedDB 仍做预算控制（从旧数据剥离超大字段，如超 2.5MB 预算剥图片并补"（图片）"占位），防单键过大拖慢读写；剥离必须浅拷贝，否则污染内存 live state。

### 7.2 关键数据独立备份

- 备份到**双存储**（localStorage + sessionStorage 独立配额兜底）；
- **版本号单调递增且 `>= Date.now()`**（防系统时间回拨）；
- **写入失败必须删旧值**：否则 stale 快照会反向掩盖新值；
- 恢复做**方向保护**：备份只允许覆盖主 key 的子集（防止旧备份覆盖新数据）；
- 显式在 action 内写备份，**不要依赖 store 的 `subscribe`**（注册晚于同步 rehydrate，首次操作被误判为初始化跳过）；
- **TDZ 坑**：被模块加载期间同步执行代码引用的顶层常量必须**前置定义**；`onRehydrateStorage` 回调在模块加载完成前被调用，引用后定义的常量会抛错被吞 → 恢复永远失败；恢复逻辑放 `merge` 而非 onRehydrateStorage。

### 7.3 导出 / 清空 / 备份

- **数据导出/清空必须覆盖全部表/键**：新增表/字段时同步更新导出和清空函数（曾只导 2 张表漏掉聊天/书信）；迁移/清理逻辑加**版本标记**确保只执行一次；
- 备份/恢复**直接读写存储键**（绕过 store 内部结构，版本兼容性更好）；恢复后 `location.reload()` 让各 store 重新 hydrate；
- 导出文件下载统一模板：`Blob` → `createObjectURL` → 临时 `a` 挂 body → click → remove → `revokeObjectURL`（revoke 在 removeChild 之后）；
- 排序**不要用 "HH:MM" 字符串**（`new Date("14:30")` 是 Invalid Date），用 id 内嵌时间戳；
- 删除/合并类操作必须同步校正派生统计，用 `Math.max(0, ...)` 防负数。

### 7.4 文件解析

- **PNG zTXt 解压的 SharedArrayBuffer 坑**：`file.arrayBuffer()` 可能返回 SharedArrayBuffer，直接喂 `DecompressionStream` 类型不兼容 → 先复制到独立 ArrayBuffer；
- jszip 解包多文件 ZIP：跳过目录项（`entry.dir`），按扩展名优先级排序（json > md > txt）取最高优先级文件；
- 聊天记录导入：多形态解析 + **保守说话人识别**（句子结尾带标点判为普通句子，排除误识别）+ 只学目标角色的发言不学用户 + 空结果报错提示检查格式。

## 八、AI 功能设计

### 8.1 降级与容错

- **多级降级**：完整 AI → 免费额度 → 离线关键词匹配 → 关闭；自动切换、状态可见；
- **AI 增强必须异步非阻塞**：保存成功后异步触发分析，不能卡用户操作；
- 降级内容要有**可辨识标记**（如 mock 回退消息注明"AI 调用失败，已用模拟回复"），防用户误以为失败内容是真实回复；
- mock 数据只做首次启动兜底，**不要用改 mock 来"模拟"问题**（会掩盖真实 bug）。

### 8.2 多服务商兼容

- 多提供商统一走 OpenAI 兼容接口（只切 baseURL + API Key）；
- **max_tokens 按服务商钳制**：如智谱视觉模型上限 1024，超了直接 400；新增服务商时在限制表补规则；
- **视觉子代理不传 `detail` 字段**：OpenAI 原生可选，但 qwen-vl / glm-4v / one-api 网关可能拒绝该字段导致 400——"可选项"在不同兼容实现里可能是"毒选项"，按最保守字段发送；
- 模型列表拉取兜底：按 baseUrl 补已知模型，不依赖服务商 `/models` 一定返回；
- **SSE 流式解析**：`TextDecoder` 必须 `{ stream: true }`（多字节字符跨 chunk 边界截断会乱码）；按 `\n\n` 切事件、保留跨 chunk 半条事件、`[DONE]` 返回、无法解析的行跳过；
- **超时 + 双向 AbortController**：内部 setTimeout abort + 外部 signal 监听（`{ once: true }`）转 abort；请求结束（含异常分支）必须 `removeEventListener`，否则监听器累积；
- 连续同角色消息要合并（多家 API 要求 user/assistant 交替）；
- 联网搜索软标记（如 `[[SEARCH:...]]`）：首次调用强制**非流式**（标记流式展示会穿帮）→ 检测到标记 → 带结果二次生成；失败剥标记兜底，不把标记露给 UI。

### 8.3 提示词与上下文

- 前端直连 AI 有 API Key 暴露、CORS 限制等 tradeoff，适合 MVP/比赛，正式产品需后端代理；
- 意图解析：关键词提取清理连接词残留（"记个心情和备注"尾部残留"和备注"）；双路径"本地优先、AI 补充"（confidence ≥ 阈值才覆盖本地）；
- 长文本按行边界切片（避免切断语义单元）；用户提问不应被吸收进记忆库。

## 九、AI 协作开发方法论

> 这是两个项目共同验证的**最高价值经验**——AI 辅助开发怎么少走弯路。

1. **排查顺序决定效率**：环境/配置类问题（输入法、键盘、打包）**先对比参照项目配置 → 再怀疑自己的代码**。曾有项目输入法问题 Web 层折腾 5+ 轮无效，对比配置 10 分钟解决；
2. **"它正常"是最强线索**：用户说"另一个 app 正常"，就意味着差异一定存在——逐项 diff 所有配置、依赖、代码，**差异项即嫌疑项**；
3. **AI 容易"反复在同一个错误方向努力"**：一轮无效后要主动换思路（改代码 → 改配置），并在总结里诚实记录哪些轮次是弯路；
4. **改任何代码先跑构建**（`npm run build` / `npx tsc --noEmit && npx vite build`），过了再交付；
5. **多 dev server 端口并存是事故源**：用户可能开着旧端口旧代码，测出"还没修好"——**代码里打版本标记日志**（如 `console.log('[app] store version: v4')`），让用户看 Console 确认跑的是新代码；
6. **每个配置开关都有代价**：加上的配置（interactive-widget、captureInput）当时解决一个问题，可能埋另一个雷——**加配置要写注释说明"为什么加"**；
7. **重大修复打版本标记 + 双保险兜底**：系统级行为（edge-to-edge、配额）无法完全预测真机表现，留 CSS 兜底、留备份、留最小空白；
8. **Playwright 无头验证**（手机视口 390×844）：逻辑类问题能自动化；但**状态栏高度、键盘避让、输入法行为必须真机验证**，无头测不出来；
9. **交付前检查**：TODO/FIXME 清零、console.log 只留版本标记、死代码清理、定期代码体检成为发布前固定步骤；
10. **重要经验要沉淀**：避坑指南 + 项目交接文档 + 跨会话记忆库，让下一轮开发不用重新踩坑。

## 十、设计与视觉规范

- **颜色必须用 CSS 变量**，永远不硬编码色值（深色模式适配的唯一正确方式）；
- 深色模式不是简单反转：逐色降低明度/饱和度；深浅主题都要验证选中态对比度（主色 25% + 描边 + 加粗）；
- **禁止 emoji**：界面图标一律用 SVG 组件（自建图标系统或 lucide-react）；
- 不用灰色背景、去语气词和鸡汤文案；
- 设计令牌早期建立（色阶/灰度/圆角/阴影）；标题衬线 + 正文无衬线双字体；
- focus 环用 `box-shadow: inset`（outline 在视口边缘溢出）；
- 自建图标系统注意同类型图标差异化设计（情绪图标不能只是换表情）；
- **警惕「AI 味」**：奶油色/玻璃态/渐变/光晕/鸡汤文案 = 装饰过剩；好的设计是「看不见的设计」——用户注意内容，而非界面。

## 十一、开发环境与工具链

### 11.1 PowerShell 命令坑（Windows）

- **不支持 `&&`**：多命令用 `;` 分隔（但 `;` 不因前一条失败而停止，需手动检查或 `if ($?) {...}`）；
- **不支持 `||`**：用 `if/else` 或 `;`；
- **`HEAD@{1}` 不可用**（花括号被解释）：用具体提交哈希。

### 11.2 工具链

- 多端工具链一次性成本：Tauri 需 Rust + Cargo + NSIS（`winget install Rustlang.Rustup` 后**重开终端**）+ Visual Studio Build Tools；Android 需 JDK + Android SDK + Gradle；
- 首次 Tauri 打包 5-15 分钟、首次 APK 10+ 分钟是正常的（全量编译），后续增量快；
- 用 Git + tag 做版本管理，**不要复制整个目录备份**（会堆积大量版本目录）。

### 11.3 Git / 发布

- GitHub **不能直接删除默认分支**：先通过 API 修改默认分支再删；
- **Release 上传前必须先删旧 asset**（GitHub 不支持同名覆盖，直接上传产生重复文件）；
- 跨网络环境推送 GitHub 不稳定时，可选用 SSH 方式（`git@github.com:...`）更稳。

## 十二、发布前检查清单

- [ ] 版本号同步（前端 package.json / 桌面端配置 / 更新检查常量 / 官网下载链接 / versionCode）
- [ ] 构建通过（`npm run build` 或 `npx tsc --noEmit && npx vite build`）
- [ ] 手机端真机验证：状态栏高度、键盘弹出、输入法/语音、返回键、通知权限、页面不拥挤
- [ ] APK：先 build → 清旧资源 → `cap sync` → `gradlew clean` → `assembleRelease` → 签名验证
- [ ] EXE：`tauri:build`（确认是 `bundle/nsis/` 的 setup.exe，WebView2 为 offlineInstaller）
- [ ] 产物重命名并归档，versionCode 已递增
- [ ] 更新日志 / 交接文档 / 版本标记日志
- [ ] GitHub：push → release create → 先删旧 asset 再上传
- [ ] 同步官网（下载链接）与在线版（构建产物，注意路径结构）
- [ ] TODO/FIXME 清零、死代码清理、无残留 console.log（版本标记除外）

## 十三、Top 15 最值得记住的教训

1. **APK 必须「先构建再 `cap sync` + `gradlew clean`」**，否则发布的是旧代码/残留资源的包；
2. **桌面端必须打包 setup 安装包（WebView2 offlineInstaller）**，否则用户装了打不开；
3. **键盘/输入法类怪问题先对比参照项目的原生配置，再怀疑 Web 代码**——Web 层折腾 5 轮不如配置对比 10 分钟；
4. **键盘高度只写 CSS 变量，不要 setState**——重渲染会干扰输入法/语音听写；
5. **Android 15+ edge-to-edge 是强制默认行为**——状态栏/安全区必须主动避让，实测高度 + 最小空白双保险；
6. **localStorage 5MB 配额是移动端数据血泪**——迁 IndexedDB 或做预算裁剪 + 关键数据双存储备份；
7. **状态管理 selector 必须稳定引用**（包括空数组/空对象字面量）——否则无限重渲染；
8. **对 DOM 唯一绑定的库绝不能同时渲染两个实例**（CSS hidden 也不行）；
9. **WebView ≠ 浏览器**：SW 要注销、通知走原生、剪贴板要降级、不稳定的移动端功能宁可隐藏；
10. **手机图片存 base64 前必须压缩**（5MB → 200KB）；PNG→JPEG 先铺白底；
11. **版本号/versionCode 不同步 = 用户下错版本**；Release 上传先删旧 asset；
12. **数据导出/清空必须覆盖全部表/键**；存储结构变更必须提升版本号；
13. **keystore 密码不要明文入库**，key 文件加 .gitignore；
14. **跨 store 派生统计防"复活"**：异步回调前判断数据仍存在 + 一次性重算迁移任务；
15. **拖拽/高频回调用 ref 而非 state**（闭包陷阱）；`touchend` 后 mouseup 会重复触发。

## 十四、开发工作流与经验方法

> 不仅是"避坑"，更是怎么把项目长期做下去、和 AI 高效协作、让用户省心的经验。

### 14.1 版本、备份与发布

1. **代码用 Git 推到远程仓库（如 GitHub）**：不只是协作，更是异地备份——本地硬盘损坏/误删都有救；养成"每个功能点/修复就 commit 一次"的习惯；
2. **产物上传 Release 保存**：可执行文件（exe / apk）上传 GitHub Release——既是版本归档（每个版本都有可下载产物，随时可取回），也是分发渠道（用户直接下载，不依赖你单独发文件）；
3. **本地/远程保存一个"已知可用"的好版本**：开发到稳定状态就打 tag（如 v1.0.0）或归档到固定目录——出问题时有回溯点，别等出了事才发现没有好的回退版本；
4. **应用内置"检查更新"功能**：启动时请求 Releases API 对比版本号，有新版提示用户一键更新——用户自己就能升级，不用麻烦地登网页下载；注意按平台分流下载链接（手机端 APK / 桌面端 EXE）。

### 14.2 与 AI 协作的习惯

5. **上下文过长要转移窗口，用提示词做迁移**：一个会话塞太多内容，AI 会"遗忘"早期需求（上下文有限）——感觉 AI 开始遗漏之前的内容时，开新窗口，用一段**交接提示词 + 交接文档**把项目状态完整带过去，比硬塞旧对话更可靠；
6. **养成做日志总结的习惯**：每轮开发后写更新日志（CHANGELOG）+ 交接文档，记录做了什么、踩了什么坑——下次接手（或换 AI）不用重新摸索；
7. **一个问题一直解决不了，换一个 AI 大模型试试**：不同模型思路和推理能力不同，卡住时换更贵/更高级的模型往往能突破——这点排查成本远低于继续硬耗；
8. **善用 skill（技能/playbook）**：把反复用到的流程（git 提交规范、代码审查、测试、打包）做成可复用技能，下次直接调用，不用每次重写提示词；
9. **善用 AI 自己开浏览器测试迭代**：让 AI 用浏览器自动化工具（导航、点击、截图、检查）边改边测，比手工反复验证快得多。

### 14.3 测试方法

10. **从不同环境测试**：自己的手机和别人手机可能不一样——机型、系统版本、输入法、网络都会导致不同问题；发布前借几台不同设备或请朋友帮忙测；
11. **真机 + 无头自动化结合**：逻辑类问题用无头浏览器自动化验证；状态栏高度、键盘避让、输入法这类**必须真机验证**（见第九章）。

### 14.4 设计

12. **去 AI 味：优先 SVG 图标，不用 emoji**（详见第十章）——emoji 在不同平台渲染不一致、风格难统一、观感廉价；SVG 图标完全可控，视觉一致性最好。

**文档结束。** 如果你从中学到一条有用的经验，欢迎分享给更多人；新坑随时 PR 补充。
