# 模板：发布打包检查

> 用法：准备发版时，把下面这段发给 AI 或自己对照执行。

```
准备发布版本【版本号】。请按避坑指南「打包发布检查」逐项执行并确认：

【版本号同步】检查并同步所有位置：
- 前端：package.json 的 version
- 桌面端：tauri.conf.json / Cargo.toml（Tauri）或 electron 配置
- 更新检查：代码里的 CURRENT_VERSION 常量
- 官网/演示页：下载链接中的版本号
- Android：versionCode（每轮 +1）、versionName

【桌面端】npm run tauri:build
- 确认产物是 bundle/nsis/ 下的 setup.exe（不是裸 exe）
- 确认 WebView2 是 offlineInstaller（内置运行时）

【移动端】按顺序执行：
1. npm run build（先构建前端）
2. 清旧资源：删除 android/app/src/main/assets/public
3. npx cap sync android
4. gradlew clean（防旧产物残留）
5. gradlew assembleRelease（不要用 cap build）
6. apksigner verify 验证签名

【发布】
- 产物重命名并归档（app_v{版本}.apk / xxx_setup.exe）
- GitHub Release：先 delete-asset 旧文件再 upload（同名不覆盖）
- 写更新日志（CHANGELOG）+ 更新交接文档

【真机验证清单】状态栏高度、键盘弹出、输入法/语音、返回键、通知权限、页面不拥挤
```
